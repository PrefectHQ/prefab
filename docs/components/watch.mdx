Interactive components fire `on_change` when a user interacts with them, but that only covers one source of state changes. What if state is updated by a `SetState` action, a server response, or another watcher? `Watch` fills that gap: it monitors a state key and fires actions whenever the value changes, regardless of what caused the change.

`Watch` is a non-visual component. It renders nothing — place it anywhere in the tree and it observes a key in the background.

## Basic usage

Pass the state key to watch and the action(s) to run when it changes. The new value is available as `$event`:

## Watching multiple keys

Place one watcher per key. They're independent, lightweight declarations that can coexist anywhere in the tree:

## Cascading watchers

A watcher's action can update a key that another watcher is monitoring. In this example, changing either dimension triggers the area watcher, which triggers the status watcher:

```python
Watch("width", on_change=SetState("area", "{{ width * height }}"))
Watch("height", on_change=SetState("area", "{{ width * height }}"))
Watch("area", on_change=SetState("status", "{{ area > 5000 ? 'Too large' : 'OK' }}"))
```

The renderer's depth limit (10 levels) prevents infinite loops. If a cascade exceeds this, it stops and logs a warning.

## Batching

When an action chain writes to multiple state keys in sequence, watchers fire once after all writes settle — not after each individual write. This is because watchers evaluate after React commits the render, so intermediate states are never observed. You don't need to worry about a watcher seeing a half-updated state.

## API reference

| Prop | Type | Description |
|------|------|-------------|
| `key` | `str \| Rx` | State key or template expression to watch. |
| `on_change` | `Action \| list[Action]` | Action(s) to fire when the value changes. The new value is available as `$event`. |
